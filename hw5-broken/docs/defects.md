# Разбор пяти дефектов

## Дефект 1: Валидация не считается — обучение вслепую

**В чём был.** В `src/train.py` было `base_val = None` и ни одного вызова `evaluate()` в цикле обучения. В логе печатался только train loss, `curve_val` оставался пустым.

**Как проявлялся.** По логу невозможно было понять, учится модель задаче или запоминает примеры: train loss падает, но val неизвестен. `base_val_loss = null`, `final_val_loss = null` — метрика не с чем сравнить.

**Как исправлен.** Добавлен замер val loss **до** обучения (точка с шагом 0) и вызов `evaluate()` каждые `train.eval_every` шагов. `evaluate()` считает среднее, взвешенное числом токенов под маской (не среднее по батчам — в них разное число токенов).

**Числом.** До: `curve_val = []`, `base_val_loss = null`. После: `curve_val = [[0, 3.5752], [10, 0.207], [20, 0.109]]` — 3 точки, падение в 32 раза. Проверка 1 — зелёная.

## Дефект 2: Learning rate слишком большой

**В чём был.** В `params.yaml` стояло `train.lr: 1.0e-2`. Для LoRA-адаптера это огромное значение: типичный диапазон — 1e-4…2e-4. За 3 шага train loss **вырос** с 2.08 до 3.74, val ушёл в 5.57.

**Как проявлялся.** Симптом из README — «train loss взлетает до десятков, остаётся выше, чем был». Обучение доходило до конца, но ухудшало модель.

**Как исправлен.** `lr: 2.0e-4` в `params.yaml`.

**Числом.** До: шаг 3/3 train 3.7392, val 5.5720 (выше базы 2.08). После: шаг 3/3 train 1.3151, val 0.4176. Финальный прогон: `train 2.188 → 0.090`, `val 3.58 → 0.109`. Проверка 2 — зелёная.

## Дефект 3: Заморозка первых слоёв ничего не меняла

**В чём был.** В `lora_config()` параметр `freeze_first` принимался, но **не использовался**. Не было `layers_to_transform` — peft навешивал адаптеры на все 28 слоёв независимо от варианта.

**Как проявлялся.** Симптом из README — «эксперимент с заморозкой 14 слоёв ничего не меняет: те же параметры, то же время». `trainable_params` в обоих вариантах совпадал, `layers_to_transform` в `adapter_config.json` пуст.

**Как исправлен.** Добавлено `kwargs["layers_to_transform"] = list(range(freeze_first, n_layers))` при `freeze_first > 0`.

**Числом.** До: оба варианта — 5 046 272 параметров. После: all_layers — **5 046 272** (0.84%), freeze14 — **2 523 136** (0.42%), ровно в 2 раза меньше. Время: 170 с против 146 с. Адаптер: 30.2 МБ против 20.55 МБ. Проверка 6 — зелёная.

## Дефект 4: Токенизатор не сохранялся рядом с адаптером

**В чём был.** В `src/train.py` после `model.save_pretrained(adapter_dir)` не вызывался `tokenizer.save_pretrained(adapter_dir)`. А `src/compare.py` в `load_adapter_tokenizer` брал токенизатор из базовой модели, а не из папки адаптера.

**Как проявлялся.** Симптом из README — «у вас make compare работает, у товарища, которому вы отдали папку адаптера, — нет». У человека без базовой модели в кеше HF папка адаптера не самодостаточна: нет `tokenizer_config.json`, не из чего собрать шаблон чата.

**Как исправлен.** 
- В `train.py` добавлен `tokenizer.save_pretrained(adapter_dir)`.
- В `compare.py` `load_adapter_tokenizer` возвращает `AutoTokenizer.from_pretrained(adapter_dir)`.

**Числом.** До: в `models/adapter_all_layers/` было только `adapter_config.json`, `adapter_model.safetensors`, `README.md`. После: добавлены `tokenizer.json`, `tokenizer_config.json`, `chat_template.jinja`. Проверка 4 копирует папку в temp, поднимает с `HF_HUB_OFFLINE=1` и сверяет 5 ответов дословно.

## Дефект 5: Нет фиксации сида — два прогона не сравнимы

**В чём был.** В `src/train.py` `set_seed(tcfg["seed"])` **не вызывался**. `runtime.py` содержал функцию `set_seed`, но без `torch.mps.manual_seed` и `torch.cuda.manual_seed_all` — на MPS и CUDA инициализация тензоров и dropout оставались случайными.

**Как проявлялся.** Симптом из README — «два запуска с одним конфигом дают разные кривые и разные ответы». Проверка 5 дважды обучает по 3 шага и сравнивает `curve_train` — при отсутствии сида кривые разные.

**Как исправлен.** 
- В `train.py` добавлен `set_seed(tcfg["seed"])` в начале `main()`, до создания модели.
- В `runtime.py` в `set_seed` добавлены `torch.mps.manual_seed(seed)` и `torch.cuda.manual_seed_all(seed)` при наличии устройства.

**Числом.** До: `curve_train` разных прогонов совпадал случайно. После: проверка 5 выдаёт «train loss по шагам: [3.2548, 2.8984, 1.3151] — одинаково» для двух независимых прогонов.
