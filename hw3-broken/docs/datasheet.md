# Datasheet: новостной датасет для классификации

## Источник
- **v1**: `Kessel/bbcnews` (HuggingFace) — 2225 статей BBC News 2004-2005
- **v2**: `Kessel/bbcnews` + `fancyzhx/ag_news` (HuggingFace)

## Лицензия
- BBC News: CC BY-NC-SA 4.0
- ag_news: Apache 2.0

## Объём
- v1: 1392 строк (collect) → 1322 (clean) → train 1056 / val 136 / test 130
- v2: 3000 строк (collect) → 2912 (clean) → train 2275 / val 304 / test 333

## Задача
Классификация новостных текстов по темам. Формат chat (system/user/assistant).
Ответ — категория новости.

## Распределение длин
- v1: user p50=1871, p90=3152, p99=3885
- v2: user p50=382, p90=2653, p99=3755

## Сплит
- group_key: `topic` + `group_granularity: 10` (тема × подгруппа по хэшу id)
- Пропорции: 80/10/10
- Контаминация: 0 (по id, тексту, группам, near-dup)

## Переработка источника
- Разведены system-промпты на 5 вариантов
- v2 объединяет два источника (BBC + ag_news)

## Ограничения
- BBC News: 5 категорий, английский язык, 2004-2005
- Ответы однотипные («Категория: X») — законно для классификации
- v2 смешивает два стиля новостей

## Обоснование порогов diversity
Снижены относительно курсовых, потому что BBC News имеет 5 категорий,
а ответы — метки классов (законно однотипные).


# Разбор пяти дефектов

## Дефект 1: Данные в git
**В чём был**: в `.gitignore` не было `data/`, поэтому `git add .` закоммитил бы JSONL-файлы.
**Как проявлялся**: `git log --stat` показывал бы крупные JSONL в истории.
**Как исправлен**: добавлены строки `data/` и `dvc_remote/` в `.gitignore`.
**Числом**: `git ls-files data/` возвращает 0 файлов.

## Дефект 2: DVC не пересчитывает пайплайн
**В чём был**: в `dvc.yaml` стадия `clean` не имела `data/raw.jsonl` в `deps`, а `collect` — не имела `params: - collect`.
**Как проявлялся**: `make v1` → `make v2` давал «didn't change, skipping», данные оставались от v1.
**Как исправлен**: в `collect` добавлены `params`, в `clean` — `deps: [data/raw.jsonl]`.
**Числом**: `dvc metrics diff HEAD~1 HEAD` показывает `rows_written: 1392 → 3000`.

## Дефект 3: Контаминация train/test
**В чём был**: `split.py` делал случайный сплит, из-за чего тема попадала в train и test.
**Как проявлялся**: `check_contamination.py` находил `group_overlap > 0`.
**Как исправлен**: введён `src/groups.py` с `make_group_key`, `split.py` использует групповой сплит, `contamination.py` использует ту же функцию.
**Числом**: `contamination.group_overlap: 0`, `near_dup_pairs: 0`.

## Дефект 4: Near-dup не ловится
**В чём был**: в `clean.py` стоял `# TODO`, near-dup не работал.
**Как проявлялся**: почти одинаковые примеры переживали очистку.
**Как исправлен**: добавлен вызов `near_duplicates()` с `normalize_text(ex.user)`.
**Числом**: `clean.py` сообщает `near-dup -24` (v1), `-38` (v2).

## Дефект 5: Гейт разнообразия не падает
**В чём был**: в `diversity.py` стоял `print("предупреждение...")` вместо `raise`.
**Как проявлялся**: вырожденный набор проходил пайплайн целиком.
**Как исправлен**: заменено на `raise DiversityError(...)` + печать каждого нарушения.
**Числом**: `check.sh` №6 — «гейт упал и назвал 4 нарушенных порога».
